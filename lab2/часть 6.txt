Пункт 6. Квота и снапшот

Начнём с квоты (диски не нужны), а для снапшота подготовим диски.
6.1. Квота на volume1

На node1:
vlad@node1:~$ sudo gluster volume quota volume1 enable
volume quota : success
vlad@node1:~$ sudo gluster volume quota volume1 limit-usage / 10MB
volume quota : success
vlad@node1:~$ sudo gluster volume quota volume1 list
                  Path                   Hard-limit  Soft-limit      Used  Available  Soft-limit exceeded? Hard-limit exceeded?
-------------------------------------------------------------------------------------------------------------------------------
/                                         10.0MB     80%(8.0MB) 512Bytes  10.0MB              No                   No
vlad@node1:~$ 

Проверка на client (запись больше лимита):
vlad@client:~$ sudo dd if=/dev/zero of=/mnt/volume1/big.bin bs=1M count=20
20+0 records in
20+0 records out
20971520 bytes (21 MB, 20 MiB) copied, 0,101608 s, 206 MB/s
vlad@client:~$ df -h /mnt/volume1
Файловая система Размер Использовано  Дост Использовано% Cмонтировано в
node1:/volume1      10M          10M     0          100% /mnt/volume1
vlad@client:~$ 

Ожидается ошибка Disk quota exceeded. Остановка может случиться не ровно на 10 МБ, это нормально. Заодно df покажет размер тома, равный лимиту квоты.

Квоту можно ставить и на каталог. На client:
vlad@client:~$ sudo mkdir /mnt/volume1/dir1
mkdir: невозможно создать каталог «/mnt/volume1/dir1»: Превышена дисковая квота
vlad@client:~$ 

На node1:
vlad@node1:~$ sudo gluster volume quota volume1 limit-usage /dir1 2MB
quota command failed : Failed to get trusted.gfid attribute on path /dir1. Reason : Нет такого файла или каталога
please enter the path relative to the volume
vlad@node1:~$ sudo gluster volume quota volume1 list
                  Path                   Hard-limit  Soft-limit      Used  Available  Soft-limit exceeded? Hard-limit exceeded?
-------------------------------------------------------------------------------------------------------------------------------
/                                         10.0MB     80%(8.0MB)   20.0MB  0Bytes             Yes                  Yes
vlad@node1:~$ 

Снова на client:
vlad@client:~$ sudo dd if=/dev/zero of=/mnt/volume1/dir1/f.bin bs=1M count=5
dd: не удалось открыть '/mnt/volume1/dir1/f.bin': Нет такого файла или каталога
vlad@client:~$ 
Здесь запись остановится около 2 МБ.


Очистка и откат (на client, затем на node1):
vlad@client:~$ sudo rm -f /mnt/volume1/big.bin /mnt/volume1/dir1/f.bin
vlad@client:~$ 

vlad@node1:~$ sudo rm -f /mnt/volume1/big.bin /mnt/volume1/dir1/f.bin
vlad@node1:~$ 

vlad@node1:~$ sudo gluster volume quota volume1 remove /dir1
quota command failed : Failed to get trusted.gfid attribute on path /dir1. Reason : Нет такого файла или каталога
please enter the path relative to the volume
vlad@node1:~$ sudo gluster volume quota volume1 list
                  Path                   Hard-limit  Soft-limit      Used  Available  Soft-limit exceeded? Hard-limit exceeded?
-------------------------------------------------------------------------------------------------------------------------------
/                                         10.0MB     80%(8.0MB) 512Bytes  10.0MB              No                   No
vlad@node1:~$ 

Квоту на корне тома оставьте для отчёта включённой или отключите, как преподаватель попросит: sudo gluster volume quota volume1 disable.

6.2. Подготовка бриков на LVM для снапшотов

Снапшоты в GlusterFS работают только на брике, расположенном на thin-provisioned LVM. Поэтому volume2 пересоберём на LVM-бриках на node1 и node2. Данные в нём (40 тестовых файлов) при этом пропадут, но они нам больше не нужны.

6.3. Снапшот volume2

Снапшот создаёт LVM-снимок тома на каждом брике одновременно. Для него все брики должны быть в сети.

Создание

На node1:
vlad@node1:~$ sudo gluster snapshot create snap1 volume2 no-timestamp
snapshot create: success: Snap snap1 created successfully
vlad@node1:~$ sudo gluster snapshot list

vlad@node1:~$ sudo gluster snapshot info snap1

Имитация аварии

На client удалите и измените данные:
vlad@client:~$ sudo rm /mnt/volume2/data.txt /mnt/volume2/s1.txt
vlad@client:~$ echo "changed after snapshot" | sudo tee /mnt/volume2/s2.txt
changed after snapshot
vlad@client:~$ echo "new file" | sudo tee /mnt/volume2/new.txt
new file
vlad@client:~$ ls /mnt/volume2
new.txt  s2.txt  s3.txt  s4.txt  s5.txt
vlad@client:~$ cat /mnt/volume2/s2.txt
changed after snapshot
vlad@client:~$ 

Восстановление

Откат возможен только при остановленном томе. На client:
vlad@client:~$ sudo umount /mnt/volume2
vlad@client:~$ 

На node1:
vlad@node1:~$ sudo gluster --mode=script volume stop volume2
volume stop: volume2: success
vlad@node1:~$ sudo gluster --mode=script snapshot restore snap1
Snapshot restore: snap1: Snap restored successfully
vlad@node1:~$ sudo gluster volume start volume2
volume start: volume2: success
vlad@node1:~$ sudo gluster snapshot list
No snapshots present
vlad@node1:~$ 

После успешного restore снапшот расходуется, и snapshot list покажет, что снапшотов нет. Это нормальное поведение.

На client:
vlad@client:~$ sudo mount -t glusterfs node1:/volume2 /mnt/volume2
vlad@client:~$ ls /mnt/volume2
data.txt  s1.txt  s2.txt  s3.txt  s4.txt  s5.txt
vlad@client:~$ cat /mnt/volume2/data.txt
before snapshot
vlad@client:~$ cat /mnt/volume2/s2.txt
2
vlad@client:~$ 

Должны вернуться data.txt (before snapshot) и s1.txt, в s2.txt будет исходное значение 2, а файла new.txt не должно быть.

Удаление снапшота (отдельная демонстрация)

На node1 создайте ещё один снапшот и удалите его:
vlad@node1:~$ sudo gluster snapshot create snap2 volume2 no-timestamp
snapshot create: success: Snap snap2 created successfully
vlad@node1:~$ sudo gluster snapshot list
snap2
vlad@node1:~$ sudo gluster --mode=script snapshot delete snap2
snapshot delete: snap2: snap removed successfully
vlad@node1:~$ sudo gluster snapshot list
No snapshots present
vlad@node1:~$
