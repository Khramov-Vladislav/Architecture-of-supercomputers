# Лабораторная работа № 3: исследование кэш-памяти

## Цель

Экспериментально исследовать характеристики иерархии кэш-памяти компьютера и сопоставить полученные оценки с данными операционной системы и документацией процессора.

## Что требуется определить

1. Размеры уровней кэш-памяти.
2. Размер кэш-строки для L1 и, если измерения позволяют сделать вывод, для более низких уровней.
3. Степень ассоциативности L1. Для L2 отдельно указать, можно ли достоверно определить ассоциативность выбранным пользовательским методом.
4. Дополнительно оценить эффективную скорость обработки массива для последовательного обхода и объяснить, почему эта величина не является прямым измерением пропускной способности DRAM.

## Экспериментальная программа

Реализовать программу на C, собираемую с оптимизацией `-O2`, с режимами измерения размера кэша (`size`), кэш-строки (`line`) и ассоциативности (`assoc`). В качестве основного метода применять обход зависимой цепочки индексов: каждый узел содержит индекс следующего, а переход выполняется как `p = a[p]`. Адрес следующего обращения должен зависеть от результата текущего чтения, чтобы ограничить векторизацию, параллельное выполнение независимых загрузок и аппаратную предвыборку.

Для каждого измерения выполнить прогревочные проходы и затем отдельный замер; повторить цикл не менее пяти раз. Сохранять минимум, среднее и медиану времени на обращение. Параметры прогрева и число повторов должны быть явно заданы в программе и описаны в отчёте.

## Методика по режимам

### Размер кэша

Измерить среднее время зависимого случайного обхода для рабочих наборов от 4 КиБ до 256 МиБ. По мере превышения ёмкости очередного уровня ожидать ступенчатого увеличения задержки. По положениям переходов оценить размеры кэшей, учитывая шум, TLB, общую кэш-память и особенности процессора. Не выдавать визуальную оценку за точное аппаратное значение без подтверждения системными данными.

### Размер кэш-строки

Провести два измерения:

* последовательный обход с разными шагами использовать как оценку эффективной скорости обработки и наглядную иллюстрацию пространственной локальности; отметить, что такой цикл может использовать предвыборку и векторизацию;
* зависимую цепочку со случайным порядком узлов использовать для оценки задержки и поиска скачков около границ строк. Проверить смещения по обе стороны предполагаемых границ, не делая вывод только по одному графику.

Если переход для L1 виден, оценить его отдельно. Для L2 и последующих уровней вывод формулировать с учётом неоднозначности: размер строки ОС может быть системным параметром, но слабый или отсутствующий переход сам по себе не доказывает конкретный размер строки.

### Ассоциативность

Построить конфликтный обход нескольких фрагментов, адреса которых рассчитаны на попадание в один набор, и постепенно увеличивать число участвующих строк. Оценить ассоциативность L1 по изменению задержки при добавлении строки сверх предполагаемого числа каналов. Объяснить, почему результат такого теста из пользовательского процесса не позволяет надёжно определить физические наборы L2: физические адреса и распределение по наборам недоступны программе, а измерение может включать конфликты L1 и эффекты TLB.

## Проверка и представление результатов

1. Собирать программу и запускать режимы воспроизводимым скриптом.
2. Записывать исходные CSV-файлы, параметры системы и результаты повторных прогонов.
3. Строить графики зависимости времени от размера рабочего набора, шага/смещения и числа конфликтующих строк.
4. Для выводов использовать несколько повторов и явно обозначать, какая статистика показана (минимум, среднее или медиана).
5. Сопоставлять экспериментальные оценки с параметрами, сообщаемыми ОС, и объяснять расхождения.

## Содержание отчёта

Отчёт должен включать постановку задачи, краткую теорию кэш-памяти и предвыборки, описание метода и параметров эксперимента, сведения о компьютере и компиляторе, графики и анализ результатов, ограничения каждого метода и заключение по каждому пункту задания. Рядом с каждым графиком объяснить, что измерялось, какой переход или закономерность наблюдается и насколько уверенно из этого следует вывод.

## Критерии корректности

* Измеряется задержка зависимых обращений, а не просто время цикла, который компилятор может векторизовать или удалить.
* Для каждого повтора порядок действий одинаков: прогрев, затем один измеряемый проход; такие повторы включены в общий цикл.
* Выводы разделяют непосредственно измеренные значения и интерпретацию аппаратных характеристик.
* Для каждого результата названы ограничения метода; в частности, ассоциативность L2 не объявляется достоверно измеренной, если программа не контролирует физические адреса.
