# Теория к лабораторной работе № 3: исследование кэш-памяти

Этот материал объясняет, что именно измеряет программа лабораторной, как читать её графики и где заканчиваются выводы, которые можно сделать по эксперименту. Он рассчитан на подготовку к защите и не заменяет фактические результаты конкретного компьютера.

## 1. Зачем процессору кэш

Процессор выполняет инструкции быстрее, чем оперативная память успевает обслуживать произвольные обращения. Если бы при каждом чтении процессор ждал DRAM, вычислительные блоки часто простаивали бы. Поэтому между ядром и оперативной памятью размещают небольшую быструю память — кэш.

Типичная иерархия выглядит так:

```text
регистры → L1 → L2 → общий кэш последнего уровня → DRAM
  быстрее и меньше                         медленнее и больше
```

L1 обычно разделён на кэш инструкций и кэш данных. L2 чаще принадлежит одному ядру, а кэш последнего уровня может быть общим для нескольких ядер. Точная организация зависит от процессора. Поэтому в работе измеряется поведение конкретной системы, а не абстрактного «типичного компьютера».

Каждый уровень хранит копии блоков данных из нижнего уровня. При чтении возможны два основных случая:

* **попадание (hit)** — нужные данные уже есть на данном уровне;
* **промах (miss)** — данные приходится искать ниже по иерархии.

Если строка не найдена в L1, запрос может быть удовлетворён из L2, кэша последнего уровня или DRAM. Задержка обычно растёт по мере продвижения вниз. Упрощённо среднее время доступа можно представить как сумму времени проверки уровней и вероятностей промаха: чем чаще промахи в быстрых кэшах, тем заметнее задержка нижнего уровня.

## 2. Строка кэша и пространственная локальность

Кэш передаёт данные не по одному байту, а блоками фиксированного размера — **строками кэша**. Например, при строке 64 байта загрузка одного целого числа может привести к попаданию в кэш соседних байтов той же строки.

Это использует **пространственную локальность**: если программа обратилась к адресу `x`, есть вероятность, что вскоре она обратится к соседним адресам. Последовательный обход массива хорошо использует локальность: после загрузки строки несколько следующих элементов могут уже находиться рядом в кэше.

Важно различать:

* **размер строки** — сколько смежных байтов перемещается как один блок;
* **задержку** — сколько времени занимает одно зависимое обращение;
* **пропускную способность** — сколько данных передаётся за единицу времени при потоке обращений.

Эти величины связаны, но не взаимозаменяемы. Один последовательный проход может показывать высокую пропускную способность и при этом ничего точно не говорить о задержке случайного чтения.

## 3. Почему обычный цикл не всегда измеряет память

Рассмотрим цикл, который читает элементы подряд. Процессор часто заранее распознаёт шаблон и **предвыбирает** следующие строки до того, как программа запросит их. Он также может выполнять несколько независимых загрузок одновременно. Компилятор с `-O2` иногда векторизует такой цикл: одна машинная инструкция обрабатывает сразу несколько элементов.

Поэтому время последовательного цикла зависит сразу от многих механизмов:

* предвыборки процессора;
* параллельных обращений к памяти;
* векторных инструкций;
* кэширования и пропускной способности;
* работы компилятора.

Это нормально для оценки скорости типового кода, но мешает изолированно измерять задержку одного обращения.

## 4. Обход зависимой цепочки указателей

В основной методике каждый элемент хранит индекс следующего элемента:

```c
p = a[p];
```

Чтобы узнать адрес следующего чтения, необходимо сначала получить значение текущего элемента. Возникает цепочка зависимостей:

```text
прочитать a[p0] → получить p1 → прочитать a[p1] → получить p2 → …
```

Процессор не может заранее вычислить адрес `a[p2]`, пока не получил `p1`. Если узлы соединены в случайном порядке, простая аппаратная предвыборка не может надёжно угадать следующий адрес. Это уменьшает влияние предвыборки и параллелизма независимых загрузок, поэтому время перехода ближе к **задержке** чтения.

Перемешивание выполняется при построении цепочки, до измеряемого участка. Измеряется уже обход готового цикла, а не генерация случайных чисел.

В исходном коде лабораторной узлы содержат `uint32_t` — 32-битные индексы. Это компактнее настоящих 64-битных указателей, но зависимость адреса остаётся той же: значение узла определяет индекс следующего чтения.

### Роль оптимизации компилятора

Оптимизатор может удалить вычисления, результат которых нигде не используется. В программе итог обхода записывается в `volatile`-переменную `sink`. Само чтение элементов цепочки также выполняется через `volatile`-квалифицированный доступ. Это делает обращения наблюдаемыми для компилятора и мешает ему заменить весь цикл пустым вычислением.

Ключ `-O2` при этом оставлен: программа должна измеряться в обычном оптимизированном варианте, а не в искусственно замедленном режиме `-O0`. Зависимость между чтениями ограничивает векторизацию именно основного теста задержки. Последовательный контрольный метод остаётся другим по природе и может использовать оптимизации и предвыборку.

## 5. Прогрев, повторы и статистика

Первый проход может быть нетипичным: данные ещё не загружены в кэш, страницы могут быть не затронуты, а частоты и состояние процессора — изменяться. Поэтому перед измерением выполняются **прогревочные проходы** (`WARMUP`). Затем измеряется один проход. Эта последовательность повторяется (`TRIALS`) раз:

```text
повтор 1: прогрев → измеряемый проход
повтор 2: прогрев → измеряемый проход
...
```

В программе заданы два прогревочных прохода и пять измеряемых повторов. Для каждого набора вычисляются:

* **минимум** — лучший зарегистрированный результат; часто ближе к работе без случайных задержек ОС, но чувствителен к малому числу повторов;
* **среднее** — сумма результатов, делённая на их количество; реагирует на выбросы;
* **медиана** — центральное значение после сортировки; устойчивее среднего к единичным выбросам.

Пять повторов дают небольшую выборку. Поэтому график показывает характерные переходы, а не лабораторную точность до долей наносекунды. Фоновая нагрузка, планировщик ОС, температура и частота процессора могут менять измерения.

Время измеряется монотонными часами. Для зависимой цепочки длительность прохода делится на число переходов, поэтому результат выражается в наносекундах на обращение. Это **средняя задержка одного перехода в конкретном цикле**, а не гарантированная задержка любого обращения к памяти.

## 6. Эксперимент 1: оценка размеров кэшей

Программа меняет размер рабочего набора от 4 КиБ до 256 МиБ. Для каждого размера строится случайная цепочка, проходящая по одному узлу в каждом блоке заданного шага. Шаг по умолчанию — 64 байта. Таким образом, увеличение размера массива увеличивает число строк, участвующих в цикле.

Пока рабочий набор помещается в L1, большинство чтений обслуживается L1 и задержка невелика. После превышения ёмкости L1 часть обращений начинает обслуживаться нижним уровнем, и время растёт. Когда набор перестаёт помещаться в L2, возможен следующий переход. Для ещё больших наборов заметнее становятся кэш последнего уровня и DRAM.

Ожидаемая форма графика — участки относительно стабильной задержки и переходы к более высоким значениям. Переходы не обязаны быть идеально резкими: кэши могут быть общими, ассоциативными, предварительно заполненными, а аппаратная политика замещения и прочие факторы влияют на результат.

Размер кэша в байтах не всегда равен точке, где кривая начала расти. На переход влияют конкурирующие данные, число потоков и ядер, TLB, размер страницы, включённость и общность уровней. Поэтому эксперимент даёт оценку ёмкости/границ уровней, которую следует сопоставить с параметрами ОС или спецификацией процессора.

## 7. Эксперимент 2: оценка размера строки

В программе есть два метода, и у них разные цели.

### Метод A: последовательный шаг

Массив проходит с шагом от 4 до 4096 байт. Элементы изменяются, поэтому компилятор не может считать проход бесполезным. Этот тест показывает, как меняется время обработки массива при разных шагах, и иллюстрирует локальность и эффективную скорость цикла.

Но метод A не изолирует задержку и не «обманывает» предвыборку: наоборот, последовательный шаблон удобен для аппаратной предвыборки, а некоторые варианты могут векторизоваться. Поэтому им нельзя в одиночку точно определить размер строки.

### Метод Б: два узла в случайной цепочке

В каждом 256-байтовом блоке создаются два последовательных узла цепочки. Первый узел ведёт ко второму со смещением `d`, второй — в следующий блок случайного порядка. Проверяются смещения вокруг предполагаемой границы строки.

Если оба узла лежат в одной строке, загрузка первого может принести в кэш и второй. Когда смещение переносит второй узел в другую строку, второе обращение может потребовать дополнительную загрузку. Поэтому время пары чтений способно увеличиться около границы строки.

Почему программа умножает время одного перехода на два? В цикле измеряется среднее время на узел; в каждой паре два узла, поэтому значение переводится во время на пару. Это упрощает сравнение «оба чтения в одной строке» с вариантом, где второе чтение пересекает границу.

В отчёте для конкретной машины заметен скачок L1 около смещения 64 байта. Это согласуется с 64-байтовой строкой L1. Для больших уровней эффект может быть слабее: обращения затрагивают несколько уровней, влияют кэш последнего уровня и DRAM. Системное значение размера строки служит полезной проверкой, но не превращает неясный график в прямое измерение.

## 8. Эксперимент 3: ассоциативность

Кэш обычно разбит на **наборы**, каждый набор содержит несколько мест — **каналов** (ways). Строка памяти с данным индексом набора может храниться в одном из его каналов. Если набор 8-канальный, он может одновременно удерживать восемь разных строк, отображающихся в этот набор.

В тесте строится цикл из `N` фрагментов. Начала фрагментов разнесены на предполагаемую ёмкость кэша `C`, чтобы адреса имели одинаковые младшие биты и для теста L1 попадали в один набор. Из каждой конфликтующей строки берутся два узла, чтобы цепочка не сводилась к одному адресу. Число фрагментов увеличивается, и измеряется время обхода.

При `N`, не превышающем число каналов, строки могут одновременно оставаться в наборе. При `N = k + 1` для `k`-канального набора одна или несколько строк вытесняются. Повторное обращение к вытесненной строке приводит к промаху в L1 и увеличивает среднюю задержку. Поэтому скачок около девяти строк согласуется с 8-канальным L1.

Это косвенная оценка, а не чтение конфигурации кэша напрямую. Рост может быть постепенным, потому что не каждое обращение после вытеснения обязательно промахивается, а политика замещения и фоновые обращения влияют на результат.

### Почему оценка L2 ограничена

Для L1 индексные биты часто находятся в младшей части адреса, которая одинакова у виртуального и физического адреса внутри страницы. Поэтому пользовательская программа может построить полезный конфликтный тест, если шаг и размер страницы выбраны правильно.

У L2 нужные биты индекса обычно зависят от физического адреса. Обычная программа видит виртуальные адреса и не контролирует физическое размещение страниц. Одинаковые виртуальные смещения не гарантируют, что строки попадут в один набор L2. Кроме того, тот же обход всё равно проходит через L1 и может вызвать эффекты TLB. Поэтому кривая для L2 не даёт надёжного числа каналов; корректный вывод — указать ограничение метода.

## 9. Эффективная скорость и физическая пропускная способность

Для последовательного прохода можно вычислить отношение размера массива к времени:

\[
B_{\mathrm{eff}} = \frac{S}{t},
\]

где `S` — выбранный размер массива в байтах, а `t` — время прохода в секундах. Если `S` задан в байтах, результат получается в байтах в секунду. Для десятичных ГБ/с значение делят на `10^9`; для ГиБ/с — на `2^{30}`.

Такое отношение характеризует скорость данного программного цикла при данном шаге. Оно не учитывает точно, сколько байтов реально передано между DRAM и кэшем: при шаге больше размера элемента затрагивается только часть элементов, но кэш загружает строки; запись может вызывать дополнительный трафик; часть данных может обслуживаться кэшем. Поэтому результат нельзя без оговорок называть предельной пропускной способностью DRAM.

## 10. Как читать графики и не переинтерпретировать шум

Для каждого графика задайте себе четыре вопроса:

1. Что менялось по оси X: рабочий набор, смещение или количество конфликтующих строк?
2. Что измерено по оси Y: наносекунды на обращение, время пары или длительность прохода?
3. Где наблюдается устойчивое изменение, и повторяется ли оно в нескольких сериях/статистиках?
4. Какое объяснение согласуется с методом, и какие другие факторы могли дать похожий эффект?

Нельзя автоматически трактовать любой пик как границу кэша, а любое плато — как точную ёмкость. Сначала нужно проверить единицы, выбранную статистику, размер рабочего набора и назначение конкретного режима.

## 11. Ограничения эксперимента

* Пять повторов — небольшая выборка; минимум может случайно оказаться особенно удачным.
* Планировщик ОС может переключить поток или запустить фоновые задачи.
* Динамическая частота и температура влияют на время.
* Размер страницы и TLB могут влиять на большие случайные наборы.
* Общий кэш может использоваться другими ядрами или процессами.
* Псевдослучайный порядок затрудняет простую предвыборку, но не устраняет все аппаратные механизмы.
* Конфликтный тест оценивает ассоциативность косвенно; особенно ограничен вывод о L2.
* Последовательный тест оценивает эффективную работу кода, а не чистую задержку и не изолированный трафик DRAM.

Повторы при максимально спокойной системе делают результаты устойчивее, но не превращают пользовательский микробенчмарк в измерение с абсолютной точностью. В отчёте следует называть оценки и обсуждать их ограничения.

## 12. Как объяснить работу на защите

Краткое связное объяснение может звучать так:

> В работе исследуется иерархия кэш-памяти по времени доступа к данным. Для измерения задержки используется случайная зависимая цепочка индексов: адрес следующего чтения становится известен только после завершения текущего, поэтому процессору сложнее предвыбирать данные и выполнять независимые загрузки параллельно. Размер рабочего набора постепенно увеличивается; рост задержки показывает, что данные начинают обслуживаться более низким уровнем памяти. Размер строки оценивается по изменению задержки, когда два связанных узла оказываются по разные стороны границы предполагаемой строки. Ассоциативность L1 оценивается конфликтным обходом нескольких строк, отображающихся в один набор: рост после числа строк, помещающихся в каналы набора, согласуется с вытеснениями. Результат L2 трактуется осторожно, потому что пользовательская программа не контролирует физические адреса. Все измерения повторяются после прогрева, а результаты сравниваются по нескольким статистикам. Полученные значения — экспериментальные оценки для данного компьютера, а не универсальные константы.

### Частые вопросы преподавателя

**Почему цепочка лучше простого обхода для измерения задержки?**  
Потому что следующее чтение зависит от предыдущего. У последовательного массива адреса заранее известны, поэтому процессор может предвыбирать строки и перекрывать задержки.

**Зачем нужна оптимизация `-O2`?**  
Чтобы измерять реалистично оптимизированный код. Используемые значения и зависимая цепочка не дают компилятору удалить основной цикл; контрольный последовательный цикл может оптимизироваться, что отдельно учитывается при его интерпретации.

**Что означает рост времени при увеличении размера массива?**  
Это признак того, что рабочий набор хуже помещается в быстрый уровень и больше обращений обслуживается ниже. По точке перехода можно оценить границу, но не обязательно получить точную паспортную ёмкость.

**Почему данные L1 и DRAM имеют разную задержку?**  
L1 находится ближе к ядру и меньше, а DRAM существенно больше и расположена дальше по пути данных. Промахи в кэше требуют обращения к следующему уровню.

**Почему график размера строки может быть неидеальным?**  
На результат накладываются уровни кэша, предвыборка, случайный порядок, TLB, системный шум и статистическая вариация. Поэтому вывод делается по устойчивому скачку и проверяется системными данными.

**Что именно подтверждает скачок после восьми строк в тесте ассоциативности?**  
Он согласуется с тем, что набор L1 удерживает около восьми конфликтующих строк. Это косвенное подтверждение 8-канальной ассоциативности, а не прямое аппаратное чтение конфигурации.

**Можно ли утверждать, что измерена ассоциативность L2?**  
Нет, если программа не контролирует физические адреса и наборы L2. В таком эксперименте результат смешан с поведением L1, TLB и неизвестным размещением строк.

**Почему нельзя назвать вычисленную скорость пропускной способностью памяти?**  
Потому что формула использует размер массива и длительность конкретного цикла, но не измеряет весь физический трафик DRAM и не отделяет трафик чтения, записи, кэширования и предвыборки.

## 13. Словарь

| Термин | Значение в контексте работы |
|---|---|
| Кэш | Быстрая память, хранящая копии частей данных нижнего уровня. |
| Строка кэша | Минимальный блок данных, которым кэш обычно обменивается с соседними уровнями. |
| Рабочий набор | Данные, к которым обращается рассматриваемый участок программы. |
| Задержка | Время ожидания одного зависимого обращения. |
| Пропускная способность | Объём данных, передаваемый за единицу времени при потоке операций. |
| Предвыборка | Загрузка предполагаемо нужных данных до явного запроса программы. |
| Набор кэша | Группа мест, в которые может отображаться строка с определённым индексом. |
| Канал (way) | Одно место хранения строки внутри набора. |
| Ассоциативность | Число каналов в наборе. |
| Промах | Отсутствие запрошенных данных на проверяемом уровне кэша. |
| TLB | Кэш трансляций виртуальных адресов в физические адреса. |
